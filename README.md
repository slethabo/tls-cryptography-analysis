# TLS 1.3 Cryptography & Traffic Decryption Analysis

A practical analysis of TLS 1.3 session key usage in HTTPS communications. This project demonstrates how ephemeral session keys are derived during the TLS handshake, used for authenticated symmetric encryption, and extracted via browser key logging (`SSLKEYLOGFILE`) to inspect encrypted traffic in Wireshark.

---

## Technical Scope

This analysis focuses on the application of key cryptographic primitives within TLS 1.3:

* **Key Exchange:** Diffie-Hellman ephemeral key pairs providing Forward Secrecy (PFS).
* **Traffic Secrets:** Application traffic secret derivation and symmetric key generation.
* **Authenticated Encryption:** Confidentiality and integrity via AEAD ciphers.
* **Packet Inspection:** Live capture parsing and session decryption workflows in Wireshark.

### 3. Cryptographic Components in TLS 1.3

| Component | Function | Technical Role |
| :--- | :--- | :--- |
| **ECDHE** | Key Exchange | Establishes ephemeral pre-master secrets with Forward Secrecy. |
| **HKDF** | Key Derivation | Derives traffic secrets from the shared secret. |
| **AES-GCM / ChaCha20-Poly1305** | AEAD Encryption | Provides symmetric confidentiality and payload authentication. |
| **X.509 Certificates** | Server Authentication | Verifies server identity via public key infrastructure (PKI). |

---

### 4. Session Key Extraction & Wireshark Decryption

Setting `SSLKEYLOGFILE` forces Chrome to export the following secrets generated by HKDF:

* `CLIENT_HANDSHAKE_TRAFFIC_SECRET` / `SERVER_HANDSHAKE_TRAFFIC_SECRET`
* `CLIENT_TRAFFIC_SECRET_0` / `SERVER_TRAFFIC_SECRET_0`

![Wireshark Encrypted vs Decrypted Capture](https://github.com/user-attachments/assets/96e10203-770f-4e31-a244-6b3bcd66e03c)

When these secrets are loaded into Wireshark (`Preferences -> Protocols -> TLS -> (Pre)-Master-Secret log filename`), the packet parser recalculates the symmetric keys and decrypts the payload from raw `Application Data` into plaintext HTTP/2 streams.

---

## Technical Takeaways

* **Key Isolation:** TLS 1.3 ensures that compromising session keys only exposes the specific captured stream, preserving past and future traffic confidentiality (Perfect Forward Secrecy).
* **Authorized Inspection:** Out-of-band key logging enables passive decryption without performing a Man-in-the-Middle (MitM) attack or altering certificates, which is essential for network forensics and debugging.
* **Key Material Security:** Because `SSLKEYLOGFILE` output grants full visibility into encrypted application payloads, log files and packet captures containing key material must be handled as sensitive assets.

---

## Repository Security Notice

To prevent session exposure or leakage of sensitive request headers, raw `.pcapng` traces and generated `SSLKEYLOGFILE` outputs are excluded from this repository (`.gitignore`). All analysis was performed on self-generated traffic in a controlled local environment.
