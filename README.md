# TLS 1.3 Cryptography Analysis

## Overview

This project explores the practical application of **modern cryptography in HTTPS communication**, focusing on TLS 1.3.

The project demonstrates how cryptographic session keys are used to protect application data during communication between a browser and a server. Wireshark is used as an analysis tool to observe the encrypted TLS traffic and, in an authorized test environment, demonstrate how possession of the session keys allows the encrypted session to be decrypted.

The purpose of this project is to connect **cryptography theory with real network communication**.

## Experiment

### 1. Establish an HTTPS Connection

A browser was used to establish a TLS 1.3 connection with a web server.

The resulting traffic was captured using Wireshark.

### 2. Observe Encrypted Traffic

The captured traffic contained TLS 1.3 records carrying encrypted application data.

Without the appropriate session keys, the application-layer contents cannot simply be read from the encrypted TLS records.

### 3. Obtain Session Keys

The browser was configured to generate a TLS key log using `SSLKEYLOGFILE`.

The log contained TLS traffic secrets generated for the browser's sessions.

Examples of the types of secrets generated included:

* Client handshake traffic secret
* Server handshake traffic secret
* Client traffic secret
* Server traffic secret

### 4. Cryptographic Decryption

Wireshark was configured to use the locally generated session keys.

The captured TLS records could then be decrypted because the analysis environment possessed the appropriate cryptographic session material.

The decrypted traffic exposed the underlying application-layer protocol and data.

## What the Experiment Demonstrated

The experiment provides a practical demonstration of the relationship between **cryptographic keys and encrypted data**.

### Without the session keys

```text
Application Data
       ↓
TLS 1.3
       ↓
Encrypted Application Data
       ↓
Captured by Wireshark
       ↓
Application contents protected
```

### With the authorized session keys

```text
Encrypted TLS Data
       ↓
Session Keys
       ↓
TLS Decryption
       ↓
Application Data
       ↓
HTTP / JSON
```

## Cryptographic Significance

The experiment demonstrates an important principle of modern cryptography:

**Encryption is only useful when cryptographic keys are properly protected.**

TLS uses ephemeral session-specific cryptographic material to protect application communication. An analyst who legitimately possesses the required session keys can decrypt their own captured session for debugging, security analysis, or incident investigation.

This also demonstrates why protecting cryptographic key material is critical.

## Security Considerations

This experiment was performed using traffic generated by my own browser session.

The session-key log and raw packet captures are intentionally **not included in this repository**, because they may contain sensitive cryptographic material or session information.

No third-party traffic was intentionally captured or decrypted.
